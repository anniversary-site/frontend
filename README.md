# frontend

MOMENT 기념일 주문서 프런트엔드

피그마 원본을 바탕으로 구현한 기념일 웹사이트 주문서 프런트엔드입니다.

## 실행

- 개발: `npm run dev`
- 빌드: `npm run build`

## 화면 흐름

MAIN → 주문 시작하기 → 템플릿 선택 → 주문자 정보 및 수령일 → 콘텐츠 입력 → 주문 상세보기 → 접수 화면

디자인 파일: https://www.figma.com/design/o5SKtAyajLQZMiCLYJLyQ8/?node-id=70-2
원본의 회색 템플릿 영역과 HOOKING 문구는 그대로 유지합니다. 연결된 프로토타입 액션이 없어 화면 순서로 이동을 구성했습니다.

## 구현 범위

- 템플릿·기념일 선택, 전화번호 자동 하이픈, 필수 입력에 따른 다음 버튼 활성화
- 메인 및 서브 문구, 사진과 영상 각 4개, 파일 미리보기와 삭제
- 사진 캡션 40자, 영상 제목 15자 입력 바텀시트
- IndexedDB로 전화번호별 주문서·첨부 파일 저장, 새로고침 후 불러오기
- 모바일 768px 기준 레이아웃, 다크 모드 제외, Pretendard dynamic subset 폰트
- 로컬 파일 읽기 진행률·실패 재시도, AI 시연용 스켈레톤·예시 결과
- 토스트 2초, 바텀시트 스와이프 닫기, 키보드 가림 방지, 모션 감소 설정 지원
- 반응형 화면, 키보드 포커스, 대화상자 포커스 제어

## 아직 연결하지 않은 기능

- 주문 완료는 화면 이동만 수행합니다. 서버 접수, 결제, 문자 발송은 수행하지 않습니다.
- 가격과 계좌번호는 피그마 원본의 예시값입니다.
- AI 문장 생성은 예시 문구 추천으로 동작하며 실제 AI API를 호출하지 않습니다.
- 미리보기 및 위치 안내는 입력 내용을 확인하는 보조 화면입니다. 완성 기념일 웹사이트 디자인은 별도로 구현해야 합니다.
- 서버/API 연결은 없습니다. 저장 버튼으로 저장한 주문서는 같은 브라우저의 IndexedDB에 유지됩니다. 저장하지 않은 변경은 새로고침하면 초기화됩니다.

## 검증

프로덕션 빌드와 로컬 HTTP 응답 확인. 브라우저 시각 검증은 로컬 주소 접근 승인 거절로 수행하지 못했습니다.

## 코드 스타일과 디자인 토큰

- `src/index.css`: 공통 디자인 토큰과 기본 스타일. rem 단위는 16px을 기준으로 계산합니다.
- `src/App.css`: 화면별 스타일. 색상, 간격, 모서리, 크기 및 모션은 공통 토큰을 참조합니다.
- `.prettierrc.json`: 2칸 들여쓰기, 작은따옴표, 세미콜론 생략, 최대 줄 길이 100자.
- `npm run format`: TS, TSX, CSS 등 프로젝트 코드 정렬.
- `npm run format:check`: 포맷 통일 여부 확인.

## 라우팅 구조

React Router의 `BrowserRouter`와 `Routes`/`Route`로 화면을 연결합니다.

| URL               | 화면               |
| ----------------- | ------------------ |
| `/`               | 메인               |
| `/order`          | 주문 시작          |
| `/order/template` | 템플릿·기념일 선택 |
| `/order/info`     | 주문자 정보·수령일 |
| `/order/content`  | 문구·미디어 입력   |
| `/order/review`   | 주문 확인          |
| `/order/done`     | 완료               |

- `src/routes/AppRoutes.tsx`: 페이지와 URL 연결, 주문서 공통 form 레이아웃.
- `src/routes/paths.ts`: URL 상수.
- `src/pages/`: 각 화면 컴포넌트.
- `src/context/OrderContext.tsx`: 페이지에서 공통 주문서 상태에 접근하는 Context.
- 주문서 입력 상태는 페이지 이동 시 유지됩니다. 새로고침 후에는 주문서 불러오기에서 저장한 전화번호로 복원합니다.
- 알 수 없는 URL은 메인으로 이동합니다.
- 배포 서버에는 `/order/*` 요청도 `index.html`을 반환하는 SPA fallback 설정이 필요합니다. 로컬 Vite 서버는 이를 지원합니다.

## TypeScript

- `src/types/order.ts`: 주문서, 첨부 파일, 페이지, 팝업, Context 공통 타입.
- `tsconfig.json`: strict 모드, 타입만 검사하고 별도 JS 파일을 생성하지 않음.
- `npm run typecheck`: TypeScript 타입 검사.
- `npm run build`: 타입 검사에 성공한 뒤 Vite 빌드.

## 전화번호로 주문서 불러오기

- 기준 화면: Figma `140:239` (주문 시작하기·주문서O).
- `/order/load`: 전화번호 입력 → 조회 → 저장한 작성 단계로 이동.
- 전화번호의 하이픈은 표시용이며 저장·조회에는 숫자만 사용합니다.
- 같은 번호로 저장하면 최신 주문서 1개로 갱신됩니다. 다른 번호의 주문서는 유지합니다.
- 전화번호를 아직 입력하지 않은 단계에서 저장하면 번호 입력 다이얼로그를 표시합니다.
- 사진·영상 Blob, 캡션, 영상 제목, 입력값, 작성 단계를 함께 저장합니다. 복원 시 Blob URL을 다시 생성합니다.
- 로딩·조회 결과 없음·저장 공간 부족·잘못된 번호·파일 처리 미완료 오류를 구분합니다.
- `src/services/draftRepository.ts`의 `DraftRepository` 인터페이스를 서버 구현으로 교체할 수 있습니다.
- 브라우저 데이터를 삭제하거나 다른 기기·브라우저에서 접속하면 현재 저장 내용을 조회할 수 없습니다. 전화번호 입력은 브라우저 내 조회 조건이며 본인 인증을 수행하지 않습니다.

## 수령 기간과 추가 요금

- 시작일과 종료일을 고르며, 선택 범위는 달력에서 이어진 배경으로 표시됩니다.
- 기본 선택은 주문일 7일 이후부터 7일간입니다. 새 시작일을 클릭하면 기본 7일을 선택하고, 두 번째 클릭으로 종료일을 조정합니다.
- 시작일과 종료일을 모두 포함해 7일까지 무료, 8~14일 1,000원, 15~21일 2,000원이며 이후에도 추가 7일마다 1,000원입니다.
- 달력 하단에 선택 기간과 추가 요금을 표시하고, 주문 확인 화면의 총액에 합산합니다.
- `src/utils/period.ts`에서 날짜 계산과 요금 정책을 관리합니다.
- 저장 데이터의 `date`는 시작일, `endDate`는 종료일입니다. 이전 단일 날짜 저장본은 7일 기간으로 복원합니다.
